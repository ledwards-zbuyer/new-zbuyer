zbEstimateTray — developer guide

A "which estimates have arrived" status tray that floats over the report while the AI, AVM, and cash-offer values come back. One JS file, no dependencies, no build step, no CSS file. It's live on the Cash Value Report.

1. What it is

Call it when the report loads and it slides in: a floating card bottom-right on desktop, a full-width bottom tray on mobile (≤720px). Inside are three sections, one per estimate source, each an icon with a small checkbox badge riding its corner. While a source is still processing, the unchecked badge is the spinner — a bright segment chasing its border. When you report a value as arrived, the chase stops, the badge fills, and the check draws itself in. Once all three are in, the header flips from "Gathering your estimates…" to "All estimates in" and the tray auto-minimizes to a corner pill ("Estimates 3/3") that reopens it. The chevron minimizes it manually at any time.

2. Quick start

Everything you need

  • The file (save-as / copy): estimate-tray.js
  • Source on GitHub: ledwards-zbuyer/new-zbuyer → mockups/assets/estimate-tray.js
  • Seen in the wild: report-classic-blue.html (runs the 3/7/25-second demo on load)
  • This guide: estimate-tray-docs.html
  1. Copy estimate-tray.js into your project. That's the whole install — no package, no build step.
  2. Include the script, then call zbEstimateTray(options) once the page (report) is up. No container needed — it appends itself to <body> as a fixed overlay.
  3. Call tray.arrive(id) from each API response as the values land.
<script src="estimate-tray.js"></script>
<script>
  var tray = zbEstimateTray();       // default items: ai / avm / cash

  // as each backend call resolves:
  fetchAiEstimate().then(function ()  { tray.arrive("ai");   });
  fetchAvm().then(function ()         { tray.arrive("avm");  });
  fetchCashOffer().then(function ()   { tray.arrive("cash"); });
</script>

That's a working tray. Everything below is optional.

3. How it works

Lifecycle

  • Create — the tray slides up over the page (fixed, z-index: 400); every badge is chasing.
  • arrive(id) — that section's chase stops, badge pops and fills, check draws, label darkens. onArrive(id) fires. Calling it again for the same id (or an unknown id) does nothing.
  • All in — header text flips to titleDone, onComplete() fires, and after dismissSeconds (default 1.6s) the tray auto-minimizes to the pill. Pass dismissSeconds: 0 to leave it up.
  • Minimized — the pill shows a live count ("Estimates 2/3") even while arrivals continue, and clicking it reopens the tray. The user can minimize early with the header chevron; nothing is ever lost.

Desktop vs mobile

  • Above 720px it renders as a floating card pinned bottom-right (~430px wide, rounded, shadowed) so it reads clearly on a large viewport.
  • At 720px and below it becomes the edge-to-edge bottom tray with top-only rounding. Same markup — the switch is pure CSS, so resizing mid-flight is fine.

4. Options

OptionType / defaultWhat it does
itemsarray, ai/avm/cash 1+ of { id, label, icon }. id is what you pass to arrive(). icon is a built-in name ("ai" / "avm" / "cash" / "generic") or a raw "<svg …>" string of your own (drawn at 36px, use currentColor to pick up the theme). Omitted icon falls back to the id, then to the generic gauge.
demoobject, off Stand-in for the real calls — omit it in production. { seconds: 8 } staggers the arrivals evenly across 8s; { seconds: [3, 7, 25] } sets each item's arrival time in order.
dismissSecondsnumber, 1.6 Hold time after ALL arrive before auto-minimizing to the pill. 0 = stay up until minimized manually.
titlestring, "Gathering your estimates…" Header text while anything is still processing.
titleDonestring, "All estimates in" Header text once everything has arrived.
onArrivefunction (id) => fires per estimate as it lands.
onCompletefunction Fires once, when the last estimate lands.

Return value

var tray = zbEstimateTray({ ... });
tray.arrive("avm");   // mark a source as delivered (the real wiring)
tray.minimize();      // collapse to the corner pill
tray.open();          // reopen from the pill
tray.destroy();       // remove tray + pill, cancel timers
tray.element;         // the tray's root DOM node

5. Styling & theming

Styles inject themselves once (a <style id="zet-style"> tag). Font is inherited from <body>. Recolor with CSS variables on <body> or any ancestor — read once at build time:

body {
  --zet-check: #1D4FD7;  /* icons, badge chase + fill (default shown)  */
  --zet-line:  #E4EAF3;  /* borders, dividers, idle badge outline      */
  --zet-ink:   #14233D;  /* delivered label + pill text                */
  --zet-muted: #5C6B82;  /* waiting labels + header title              */
}

6. Good to know

  • One instance at a time. It's a fixed overlay — a second instance would sit on top of the first. Call destroy() before re-creating (the demo buttons on this page do exactly that).
  • Call it after <body> exists (end of body or on DOMContentLoaded) — it appends itself and reads theme variables from computed styles at build time.
  • It never blocks anything. Purely a status layer: no overlay backdrop, the page stays scrollable and clickable, and the user can dismiss it whenever.
  • Screen readers: the tray is a polite role="status" live region; the chevron and pill are labeled buttons.
  • Reduced motion: honors prefers-reduced-motion — no chase, no slide, checks appear instantly.
  • Browser support: anything modern (plain DOM + SVG + CSS animations; no frameworks, no polyfills).
