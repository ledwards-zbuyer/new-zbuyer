zbValueSlider — developer guide

A slider whose track is a tiny chart of your values. One JS file, no dependencies, no build step, no CSS file. Live examples of every configuration: value-slider-demo.html. Other widget guides: estimate tray · Z-beat loading.

1. What it is

You give it a list of anchors — dollar amounts (or any numbers), each with a label. It renders a horizontal track shaped like an area chart: short where the values are low, tall where they're high. The user drags the tall pill handle along the track; when they let go, it snaps to the nearest anchor and reports which one they picked. Until they interact, the headline shows the full range so no single number is presented as "the" number.

2. Quick start

Everything you need

  • The file (save-as / copy): value-slider.js
  • Source on GitHub: ledwards-zbuyer/new-zbuyer → mockups/assets/value-slider.js
  • Live examples of every configuration: value-slider-demo.html
  1. Copy value-slider.js into your project. That's the whole install — no package, no build step.
  2. Add an empty container element wherever the slider should render.
  3. Include the script, then call zbValueSlider(container, options) after the container is in the DOM.
<div id="mySlider"></div>

<script src="value-slider.js"></script>
<script>
  zbValueSlider(document.getElementById("mySlider"), {
    anchors: [
      { value: 312000, label: "Quick cash close" },
      { value: 371000, label: "Estimated market value" }
    ],
    onSelect: function (anchor, index) {
      console.log("picked:", anchor.value, anchor.label);
    }
  });
</script>

That's a working slider. Everything below is optional.

3. How it works

Anchors drive everything

  • Pass 1 to 6 anchors. They're sorted by value for you — order doesn't matter.
  • Each anchor's horizontal position is proportional to its value: the lowest sits at the left end, the highest at the right, everything else in between by value.
  • Each anchor's track height is also proportional to its value — but normalized to the min-to-max span ("auto-zoom"), so even a narrow range (say $312K to $371K) renders a full, meaningful rise instead of a flat strip. An 8px floor keeps the lowest anchor looking like value rather than nothing.
  • Between anchors the outline is smoothed with rounded curves, so it reads as a chart, not connect-the-dots. Every anchor gets a small dot with a hover tooltip.

Interaction

  • The handle drags freely; the blue fill follows it live (deepest blue always at the handle). On release it snaps to the nearest anchor.
  • The headline starts as the full range ("$312,000 – $371,000") and only swaps to a specific value once the user snaps somewhere — the snapped anchor's label appears in smaller, quieter type beneath the number. onSelect fires on every snap with the anchor object and its index.
  • The headline auto-fits: the number — or the full range — shrinks as needed so it never wraps to a second line.
  • Keyboard: the handle is focusable; arrow keys step between anchors.

The single-value mode

If you pass one anchor (or several that share one value), there is no range to explore, so the widget renders a static display: fully-filled full-height chart, handle locked in the center, no dots, no end labels — the headline shows the value with its label beneath.

4. Estimate ranges — points on the curve, ranges through them

Estimates that are ranges (an AI estimate, an AVM band, a cash-offer band) render as horizontal colored lines inside the shaded chart. With a value — the single point estimate — the dot is pinned to the curve's edge at that value's x-position (clamped into the range), the range line runs horizontally through the dot from lo to hi, and dashed verticals project each end onto the curve: down at the low end (the curve is lower there), up at the high end. Vertical position is the value mapping itself. Without a value, the line falls back to a terrace at its low end's curve height. The value domain stretches to cover every range endpoint (plus any anchors and the optional domain pin). Eight real-world shapes — agreement, disparate, wide, narrow, ties, cash discount, mixed confidence, edge points — render live on the scenario gallery.

The handle snaps to the points. With fewer than 2 anchors this is chart mode: the curve starts unfilled and the point values are the snap targets — the pill handle returns with the first point, dragging snaps to the nearest point, arrow keys step between them, and the fill — translucent here so the colored lines stay readable inside it — follows the handle. On snap, the headline shows the point value with its range as the subtext ("AI estimate · $340,000 – $358,000"); the headline rows are fixed-height, so the number never shifts vertically between the initial full-range state and snapped states.

The complete-range bar. A labeled bar under the chart spans the union of every arrived value — lowest low to highest high — growing as estimates land, with dotted risers at each end climbing to the chart's baseline to tie the bar to the graph. Until the user grabs the handle, it parks at the center of that union and the headline shows the union range, so the resting state reads as "the complete home value range" before anyone interacts.

Live while held. The headline doesn't wait for release: as the handle is dragged it ticks the dollar value under the handle (rounded sensibly), the subtext switches to whichever estimate range the handle is inside (back to the range label outside them all), that estimate's on-chart label bolds, and its dot pops as the handle glides over the point itself. Release still snaps to the nearest point.

Single values welcome: a range passed as just { id, value, label } — no lo/hi — synthesizes a ±10% range around the value, rounded to a sensible increment for its magnitude (a $349,000 AI estimate becomes $314,000 – $384,000). See "Single values only" on the scenario gallery.

Collisions: point-pinned lines can't move (the dot fixes them to the curve), so their labels dodge instead — each label takes the first clean spot of: above the line's left end, above its right end, below its right end (the widget looks ahead at every known line before placing). Valueless terrace lines still stagger apart as before. Identical AI and AVM ranges read as a tight stack whose labels sit at opposite ends.

Arrivals: addRange() + loading chips

Pass domain to pin the scale up front, then call slider.addRange(range) as each estimate comes back — the line draws in (a range outside the current domain rebuilds the widget on the wider scale). Add expected — the roster of estimates on their way — and the chart shows a loading chip per pending estimate across its top: the same chase-checkbox animation as the estimate tray, color coded per type. When that estimate lands, the box checks and the chip flies down to its range on the graph. This pairs 1:1 with the estimate tray: give the tray items the same color per estimate type and wire onArrive to addRange — chip, badge, and line all speak the same color. The Cash Value Report runs exactly that behind ?ranges=1.

var chart = zbValueSlider(el, {
  domain: { lo: 312000, hi: 371000 },
  expected: [{ id: "ai", label: "AI estimate", color: "#3BA4F4" }, ...]
});
zbEstimateTray({
  items: [{ id: "ai", label: "AI estimate", icon: "ai", color: "#3BA4F4" }, ...],
  onArrive: function (id) { chart.addRange(EST[id]); }   // EST: your shared map
});

5. Options

OptionType / defaultWhat it does
anchorsarray 1–6 of { value: number, label: string }. Label may be empty; it feeds the dot tooltips, end labels, and aria text. Optional when ranges or domain is supplied.
rangesarray 0–4 of { id, lo, hi, value, label, color } — estimate ranges drawn inside the curve (section 4). value optional: the point estimate — a dot pinned to the curve edge with the line running through it (clamped into [lo, hi]); it also becomes a handle snap target. lo/hi optional when value is present: a missing side synthesizes ±10% around the value, rounded reasonably. color optional (defaults rotate navy / sky / primary).
domain{ lo, hi } Pins the value scale with no visuals, so later addRange() arrivals draw in place instead of rescaling. Alone (no anchors/ranges) it renders the empty static chart, ready for arrivals.
expectedarray Chart mode: the roster of estimates on their way — { id, label, color } each. Renders a loading chip per pending estimate (chase checkbox + label, color coded) across the chart top; on addRange() with a matching id, the box checks and the chip flies down to the landed range. Ids already present in ranges never chip.
formatfunction, $1,234,567 Turns a value into display text everywhere it appears (headline, end labels, tooltips). E.g. v => "$" + v.toLocaleString() + "/mo".
headlineboolean, true Render the big number/range above the track (auto-fits to one line; the snapped anchor's label renders in smaller type beneath). Set false if your page already has its own headline — use onSelect to update it.
rangeLabelstring, "Complete home value range" The sub-label under the headline while it still shows the untouched full range; anchor labels take over once the user snaps. Pass "" to hide it.
endLabelsboolean, true Min and max values + labels under the track ends. Never shown in single-value mode.
onSelectfunction (anchor, index) => fires on every snap (drag release, arrow key, or snapTo).
colorsobject Per-instance colors, each key optional: handle, fillLo / fillHi (fill gradient), track (unfilled chart), dot.
ariaLabelstring Accessible name for the handle. Default "Explore the value range".

Return value

var slider = zbValueSlider(el, { ... });
slider.snapTo(2);    // snap to an anchor programmatically (0-based, sorted order)
slider.addRange({ id, lo, hi, label, color });  // draw an estimate range in
slider.anchors;      // the sorted anchor array (with computed positions)
slider.ranges;       // the range list (colors materialized as assigned)
slider.destroy();    // empty the container

6. Styling & theming

Styles inject themselves once (a <style id="zvs-style"> tag). The slider fills its container's width; height is fixed (~96px track plus headline and end labels). Font is inherited from the container.

Default colors are the classic-blue palette of the zBuyer Cash Value Report (handle #FF6B4A, fill #7FC4FF → #1D4FD7, track #E4EAF3, dots #8296B9). Two ways to recolor — script colors win over CSS variables, variables over defaults:

// per instance, in the call:
colors: { handle: "#128A46", fillLo: "#BFE8CF", fillHi: "#128A46",
          track: "#E8EFE9", dot: "#6E9B7F" }

/* or with CSS variables on the container or any ancestor: */
.my-theme { --zvs-cta: #128A46; --zvs-lo: #BFE8CF; --zvs-hi: #128A46;
            --zvs-track: #E8EFE9; --zvs-dot: #6E9B7F;
            --zvs-ink: #14233D; --zvs-muted: #5C6B82; }

7. Good to know

  • Call it after the container is in the DOM. Theming reads computed styles at build time; a detached container silently falls back to default colors.
  • Multiple instances per page are fine — each gets unique internal SVG ids and can carry its own colors.
  • All values equal? It falls back to the single-value static display instead of dividing by zero.
  • Rebuilding: there is no update method — call destroy() and re-create with new anchors (it's cheap).
  • Browser support: anything modern (uses Pointer Events and SVG; no polyfills, no frameworks). Touch, mouse, and keyboard all work.
  • Data honesty: positions and heights are both computed from your values — nothing is styled by hand, so the chart never misrepresents the spread.
